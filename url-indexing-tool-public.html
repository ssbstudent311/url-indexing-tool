● Three Modes

Speed, on your terms

The same three modes used by paid indexers — but here there are no credits to buy and no payment. Every mode sends the same 8 strong signals, including Mass Ping.

N

Normal — 1 credit/URL · drip-feed

Signals are sent one after another, with pauses. SpeedIndex-style drip schedule: bulk lists are drip-fed — after each batch (5 URLs) there is a 2-minute pause before the next batch, so it never looks like a single blast. Lighter load on services, and Googlebot usually picks the page up within a few hours. Best for everyday routine backlinks.

I

Instant — 3 credits/URL · minutes

The moment you submit, Archive.org, archive.today, Ping-o-matic, WebSub, Twingly, Blo.gs and Mass Ping (18 endpoints) all run in parallel. Discovery starts fastest here; crawling still follows Googlebot's own schedule.

G

Guaranteed — 7 credits/URL · 7 days, retry every 6 hours

The strongest mode for backlinks. After the Instant blast, the tool automatically re-checks every backlink every 6 hours for 7 days. If no archive copy (crawl evidence) is found, Archive.org, archive.today hub copy, WebSub, Ping-o-matic, Twingly and Blo.gs — all signals are fired again on the backlink, and if the hub page is live, the hub is pushed again too. Retries continue until evidence appears or the 7 days are complete. Every row shows the Guaranteed deadline, next retry and retry count live. The page must stay open — closing it stops the watch. Guaranteed means continuous retries for 7 days, not a promise of 100% indexing — the final decision is Google's.

● Discovery Signals

The 5-Protocol Engine and Mass Ping

Every submission runs the full signal set below. Each protocol and signal reports its own real status — verified, sent (unverified), failed or skipped.

5-PROTOCOL ENGINE — one group, a separate line for each protocol

Based on the Search-Engine-Indexer model: WebSub · IndexNow · Blo.gs · Twingly · Ping-o-matic · Wayback (Archive.org) — these 6 protocols run as one group on every submission, but in the Coverage report and every Tracking row, each protocol's real status is shown on its own line (verified / sent unverified / failed / skipped). If one protocol fails, the status of the others is never hidden.

Free Index Pre-Check, Bulk Credits and Drip Schedule

Pre-check (SpeedyIndex-style): before submission, every URL gets a Wayback snapshot check — if a snapshot is found, Tracking shows Crawled; if not, Not indexed as the pre-status. Whether Google has indexed it is verified through each row's site: “Google check” link; a false Indexed label is never shown. Bulk credits (Instant Indexer model): Normal 1 · Instant 3 · Guaranteed 7 credits/URL — total credits and batch progress are shown live on bulk submissions (credits here are for reference only, not payment). Drip (SpeedIndex-style): in Normal mode there is a 2-minute pause after every 5 URLs; Guaranteed already includes a retry every 6 hours.

Archive.org Save Signal 1 · Wayback — 5-Protocol Engine

A request is sent to the Internet Archive to fetch and save the page. A public copy is the strongest crawl evidence — the “Crawled” status is only set when that copy is found, never on a guess.

archive.today Hub Copy Signal 2

The second major archive network — a hub copy of the page is submitted. Two separate archive crawlers fetching the page makes discovery twice as strong, and the copy can be opened and inspected later.

Ping-o-matic Signal 3

An update-service ping that spreads news of new content to many services. The browser cannot read its response, so the log always records it as “sent (unverified)”.

WebSub (PubSubHubbub) Signal 4

A publish ping is sent to Google's own hub — feed and update subscribers receive the URL immediately. This is the same protocol major publishers use for new content.

Twingly Ping Signal 5

An XML-RPC ping to a blog and content search network — the URL enters their crawl system, from where other crawlers also pick it up.

Blo.gs Ping Signal 6

The oldest update ping service — weblog update news sent to their directory network. It is a small signal, but every extra route improves the chances of discovery.

IndexNow Signal 7 · Your own site

The most direct route for your own site: IndexNow tells Bing, Yandex and others about the URL immediately. The key file must be present on your site — the tool creates both the key file and the payload, and the key stays only in this session.

Mass Ping Signal 8 · MASS PING · 18 endpoints

A new signal built on the OmniSEO open-source toolkit's mass-ping method — but not its full list of 2,500; only live, reputable endpoints were selected. Every submitted URL is pinged across 18 endpoints in parallel (GET, 8-second timeout): archive.is submit, Bing search, Yandex search, DuckDuckGo, Hypestat, BuiltWith, Whois lookup (Whois.com + DomainTools), SiteChecker, SpyOnWeb, SimilarSiteSearch, SimilarWeb, URLVoid, Wappalyzer, Netcraft, SecurityHeaders, SSL Labs and Google Transparency Report. Dead or spammy domains (multiply.com, statsaholic, dealighted and similar) are not in the list. The browser cannot read their responses, so this is always recorded as “sent (unverified)” — Tracking and the CSV show each URL's Mass Ping count (for example 17/18) separately.

Hub Page + RSS Feed Backlink · Tier-2

For a random backlink, the tool builds a hub page for your site — the target's real title and description, a dofollow link, canonical and robots index,follow. After the file is uploaded to the /hub/ folder, the same 7 Tier-2 signals (archive.today hub copy, Archive.org, WebSub, Ping-o-matic, Twingly, Blo.gs, Mass Ping) are sent to the hub URL in parallel, and every hub page is included in the hub/feed.xml RSS feed.

Straightforward — no false “Indexed” claims

These signals drive discovery and crawling — whether to index is always Google's own decision, based on the page's content, quality and the site's authority. That is why the tool has only three statuses: Pending (signals sent, awaiting crawl), Crawled — not confirmed by Google (an archive copy was found, meaning a crawler has fetched the page) and Not indexed (no evidence found on checking). The same applies to Guaranteed mode: Guaranteed means the tool keeps re-firing the signals and hub push every 6 hours for 7 days until evidence appears — it is not a promise of 100% indexing, and the final indexing decision is always Google's. Any tool claiming “100% indexing guaranteed in 2–5 minutes” is making an unverifiable claim — here, the real result of every signal is shown on screen.

● Hub Page Engine

Hub Page Engine for backlinks

For URLs on other sites, the hub page is the route to Googlebot — built on your own indexed site, with a dofollow link to the target.

Hub Page Engine — The Strong Setup for Backlink Indexing For random / backlink URLs

A random link (a backlink on someone else's site) cannot be indexed directly through a Google API — the proven method is a hub page, and this engine automates exactly that. For every submitted URL, the tool fetches the target page's real title and description and builds a complete hub page with the backlink's dofollow link plus the hub page's own meta tags, canonical and robots index,follow. The hub page is then pushed to Google from your own indexed site — Googlebot crawls the hub and follows the dofollow link to the backlink page.

This address becomes every hub page's canonical and the RSS feed is based on it. If you leave it blank, the files are still created but the canonical will contain the placeholder https://your-site.com/hub/ — enter the real address and rebuild the hub before uploading.

Step 1Submit the backlink URL — the tool builds the hub page automatically (with the real title and description).
Step 2Download the hub page .html file (there is a button in every row, or download all of them below).
Step 3Upload the file to the /hub/ folder on your site — this step is required; without it, no push can happen.
Step 4Press “Hub live check” here — once the file is live, Tier-2 signals (archive.today hub copy, Archive.org, WebSub, Ping-o-matic, Twingly, Blo.gs) are sent to the hub URL in parallel.
Step 5Googlebot reaches the hub — Tier-2 signals and the hub RSS feed notify crawlers about the hub page; Googlebot crawls the hub and follows the dofollow link to the backlink. In Guaranteed mode, if the hub is live, this push repeats every 6 hours for 7 days.

The RSS feed file is named feed.xml — upload it to the same /hub/ folder on your site so its address becomes hub/feed.xml (for example https://yoursite.com/hub/feed.xml). Every new hub page is added to this feed as an item — crawlers and WebSub pick up new hub pages from this feed. For tracking, the hub status is shown live in every queue row below: hub created or not · live or not · Tier-2 signals sent or not.

Please note: The hub file is only downloaded to your computer — until you upload it to the /hub/ folder on your site, it is not live on the internet and no push will work. The live check and Tier-2 signals only take effect after upload. The final indexing decision still belongs to Google — a hub page is the strongest route to reach it, not a guarantee.

● Hub Page Engine — For Backlinks

Need a backlink indexed? The route is a hub page

A backlink lives on someone else's site — it is not your own site, so you cannot submit it directly to Google. Services such as RankLocal and MonkeyIndexer actually do the same thing: they connect the backlink from a page (a hub) on one of their indexed sites and push that hub to Google. This engine builds the same setup on your own site.

1

The hub page is built automatically

As soon as you submit a backlink, the tool fetches the target page, extracts its real title and description and builds a complete hub page — dofollow link, meta description, canonical and robots index,follow included. If the fetch fails (the site blocks the browser), a title derived from the URL is used and the row clearly states that the real title was not found.

2

Upload to the /hub/ folder — a required step

Download the hub page .html file and upload it to the /hub/ folder on your site (for WordPress, use your hosting File Manager or FTP to place it in public_html/hub/). Also place feed.xml in the same folder. Before upload, the hub page does not exist on the internet — the push happens after upload.

3

Push: signals + RSS

Once the file is live, press “Hub live check” in the queue row — Tier-2 signals (archive.today hub copy, Archive.org, WebSub, Ping-o-matic, Twingly, Blo.gs) are sent to the hub URL in parallel, and the hub/feed.xml RSS feed keeps notifying crawlers about every new hub page. Each backlink's hub status — created / live / signals sent — is tracked in its own row.

Why a hub page works

Googlebot crawls pages first when they sit on an already indexed, trusted site. When your site's hub page reaches Google through signals and the RSS feed, Googlebot follows the dofollow link from there to the backlink page — that discovery is what makes the backlink eligible for indexing. The older and better indexed the hub site, the faster the backlink is picked up. The final decision is still Google's — the content and quality of the backlink page also matter.

● Questions and Answers

Frequently asked questions

Can I submit a backlink from another site?

Yes — you can submit any public URL without Google Search Console, because archive and ping signals do not require proof of ownership. Only IndexNow is for your own site (it requires a key file). The indexing decision is still Google's, and the quality of the page carrying the backlink matters.

What is the Hub Page Engine and why does a backlink need it?

A random or backlink URL lives on someone else's site — it is not your own site, so it cannot be submitted directly to Google. The Hub Page Engine builds a page on your own site for that backlink, containing a dofollow link to it. That hub page is pushed to Googlebot through signals and RSS, and Googlebot travels from the hub to the backlink. Paid indexer services actually do the same thing — the difference is that their hub is built on their site, while here it is built on your own site.

Will the push work without uploading the hub file?

No — and this is the most common mistake. The tool creates the hub page .html file in your browser; until you upload that file to the /hub/ folder on your site, the page is not live on the internet. Upload first, confirm here with “Hub live check”, then run the Tier-2 signals — only then is the push real. The RSS feed (feed.xml) must also be uploaded to the same /hub/ folder.

How does the target's real title and description get into the hub page?

When building the hub, the tool fetches the target page from the browser, reads its <title> and meta description, and places them in the hub page's title, heading and description. Some sites block browser fetches (CORS) — the tool then tries a public proxy, and if that still fails, a title derived from the URL is used; the queue row clearly states whether the real title was found or a fallback was used.

What is the Mass Ping signal?

Mass Ping is the new 8th signal — built on the OmniSEO open-source toolkit's mass-ping method, but without its full list of 2,500 endpoints (which contains many dead or spammy domains). Only 18 live, reputable endpoints were selected: archive.is, Bing, Yandex, DuckDuckGo, Hypestat, BuiltWith, Whois, SiteChecker, SpyOnWeb, SimilarSiteSearch and more. Every URL is pinged across all of them in parallel with GET requests and an 8-second timeout, and the response is always recorded as “unverified” because the browser cannot read cross-origin responses. The queue shows the count on the MASS PING chip (for example 17/18), and the CSV includes separate mass_ping_sent / mass_ping_total columns.

What is the 5-PROTOCOL ENGINE?

Based on the Search-Engine-Indexer model, 6 protocols — WebSub, IndexNow, Blo.gs, Twingly, Ping-o-matic and Wayback (Archive.org) — run as one group. In the “5-PROTOCOL ENGINE” box in the Coverage report and in every Tracking row, each protocol's status is shown on its own line: verified, sent (unverified), failed or skipped. No combined false success is shown.

What are credits — is there a payment?

No, there is no payment. Credits are the accounting used by Instant Indexer and paid tools, shown here only as a rate card: Normal 1, Instant 3, Guaranteed 7 credits per URL. On bulk submissions, total credits and batch progress (for example 12/50 URLs, 36 credits) are shown live, and the CSV includes each URL's credits in a separate column. No credits are deducted here.

How does the free index pre-check work?

A SpeedyIndex-style checker: before submission (or at any time via the “Free index pre-check” button), every URL gets a Wayback snapshot check. If a snapshot is found, Tracking shows Pre-check: Crawled; if not, Pre-check: Not indexed. Whether it is actually indexed in Google is verified through each row's “Google check” (site:) link — a browser tool cannot confirm Google indexing itself, so no false “Indexed” label is ever shown.

What is the drip schedule (Normal mode)?

SpeedIndex-style drip-feed: in Normal mode, bulk URLs are not blasted all at once — every 5 URLs form one drip batch; when a batch completes there is a 2-minute pause, then the next batch. The drip countdown is shown live on screen and every row carries its drip batch number. The page must stay open for this; pressing Stop halts the drip. Guaranteed mode additionally runs a retry every 6 hours for 7 days.

What is the real difference between Normal, Instant and Guaranteed?

The signals are the same 8 in all three modes (including Mass Ping). In Normal they are sent one after another with pauses (crawling within ~5-10 hours is common). In Instant they all run in parallel the moment you submit. In Guaranteed — the strongest for backlinks — after Instant, an automatic re-check runs every 6 hours for 7 days: if no evidence is found, all signals are fired again on the backlink and, if the hub page is live, the hub is pushed again too, until evidence appears or the deadline completes. Every row shows the Guaranteed deadline (7 days), when the next retry is and how many retries have run — all live.

Does Guaranteed mean 100% indexing?

No — to be clear: the final indexing decision is Google's; no tool or service can honestly promise 100% indexing. Guaranteed here means only that the tool will keep retrying every 6 hours for 7 days — re-firing the signals, pushing the hub again if it is live, and showing every retry count in Tracking — until crawl evidence appears or the 7 days are complete.

What does “Crawled — not confirmed by Google” mean?

It means an archive service has fetched the page and created a copy of it — proof that a crawler has read the page. But whether the page has entered Google's index cannot be confirmed by a browser tool. Verify it yourself with each URL's “Google check” link, which runs a site: search.

Why must the page stay open for Guaranteed mode?

This is a public static tool — there is no server running in the background to keep checking for you. The automatic re-check and the 6-hour retry run in this open tab. If you close the page, the watch and retries stop there; you would need to reopen it and submit the URL in Guaranteed mode again. That is why the “Guaranteed” guarantee is continuous retries for 7 days, not indexing — the final decision is Google's.

How long will indexing take?

There is no fixed time. Crawling sometimes happens within minutes or hours, sometimes within days, and some URLs are never indexed (thin content, noindex, robots block). Instant mode starts discovery immediately — after that, the timing belongs to Googlebot.

What happens if the page is 404 or noindex?

Even if the signals are sent, Google will not index such a page. Check these first: the page is live (200 status), there is no noindex in meta robots, and robots.txt is not blocking crawling.

Where is this data saved?

Nowhere. The queue, statuses and the IndexNow key exist only in this open tab and are cleared when the page is closed. To keep a record, download the “Report CSV” — it contains every URL's mode, status and the result of every signal.

How do pay-per-result credits and the day-7 refund work?

Credits are held when you submit and are only charged when indexing evidence is confirmed for that URL. In Guaranteed mode, if no evidence is confirmed by day 7, the held credits for that URL are refunded automatically. Tracking shows Held, Charged and Refunded for every URL, and the Day-7 final report (CSV) lists the final status, page title and credit outcome for each job.

What is the site-strength drip schedule?

Choose your site strength and bulk URLs are drip-fed at a daily pace that suits it: Young site 5–15 URLs/day, Medium 20–50 URLs/day, Authoritative 50–150 URLs/day. The schedule applies in Normal and Guaranteed modes, alongside the short pause between drip batches.

What does the mobile check do?

Every submitted URL is fetched and checked for mobile readiness — viewport, page title and reachability — and the result is shown in its Tracking row. A browser cannot send a real search-engine crawler user-agent, so the result is reported honestly as a mobile-readiness check, never as a guaranteed crawler visit.

How many URLs can I send in one batch?

Up to 200 URLs can be added to the list; signals are sent to the first 50 in each run (so services are not overloaded). The rest stay in the queue — press the button again to run the next 50.
